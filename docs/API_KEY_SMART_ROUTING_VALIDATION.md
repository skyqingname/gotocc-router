# 智能路由验证记录

验证日期：2026-09-06。验证在 Windows WSL2 Ubuntu-24.04 内的 Docker 中完成，未连接生产数据库或真实模型账号。

## 实现范围

- 显式 fixed/auto Key 模式，既有 Key 默认 fixed；认证快照版本及缓存失效同步。
- 当前付款主体授权、团队生命周期、模型与协议能力校验，独立的请求级分组上下文。
- 管理员默认/精确模型/最长前缀分组优先级，目录与实际路由使用相同规则。
- 原始内容先审计，随后最终准入和模型重写；不通过运行时跨组重放改变付款来源。
- Responses/WS 共享归属、每轮身份与计费快照、状态请求原组恢复、批量任务原组及幂等读取。
- 用户、团队、管理员及支持页的模式显示，能力驱动的媒体入口，中英文文本。

## 验证中修正的问题

- 新增 routing_mode 后同步 API 契约期望与前端类型、文案键。
- 在组级审计前保留公共模型及原始请求，避免别名重写漏掉原始审计内容。
- 使用每轮不可变身份/订阅快照，避免异步账单引用下一轮状态。
- 区分原生 WS 协议拒绝与透传模式的未知帧兼容性，不放宽原生解析器。
- 本地断连用例曾受验证代理干扰；关闭测试进程代理后连续三次及全量测试通过，未改动无关的验证码实现。
- 浏览器检查改为生产构建，避免把开发服务器的首次模块编译等待混入页面验收。

## 使用边界

已知功能边界、配置示例与上线回退步骤见 [API Key 智能路由](API_KEY_SMART_ROUTING.md)。其中包含 simple 模式、单组 wham、不可证明归属的资源操作、批量余额组限制和旧实例回退要求。

本记录证明上述本地验证场景，不是对所有供应商、所有生产配置或绝对安全的承诺。生产实例应全部升级后，先用少量新智能 Key 对真实分组、账单和审计做灰度验证。
