# 受邀站长中心

## 开通与注册归属

管理员在“用户管理 → 站长设置”为指定用户开通；所有用户初始关闭。菜单、页面和管理接口都读取同一权限。关闭后停止站长管理及新的邀请注册，既有价格、客户关系、返佣比例和历史记录保留。

站长复制 `/register?reseller=RS-…` 链接。新用户注册使用现有 `user_affiliates.inviter_id` 作为唯一归属，在同一注册事务写入 `reseller_customers` 标记；邮箱和第三方注册传递同一邀请码。现有用户登录不会重新绑定。旧 AFF 客户不自动纳入站长定价。管理员沿用现有换绑入口，换绑影响后续请求，历史收益保留原受益人。

本期使用当前站点域名，不包含独立域名、白标站点或隐藏原站的承诺。

## 客户价格与收益

只显示当前直属站长客户；支持搜索、备注、整体倍率和分组倍率。成本价以站长自身可用分组价格为基础。客户倍率最低 1：客户分组覆盖 > 客户整体覆盖 > 站长默认分组覆盖 > 站长默认整体倍率。已作为他人客户的站长，其自身价格按同一关系链计算。只给直接站长记录本次消费差价。

客户价 = 站长自身价格 × 客户倍率。文本时段系数继续按 LC-020 生效；图片和视频使用各自基础倍率乘客户倍率，不叠加文本时段系数。分组权限定价不会自动授予客户订阅或专属组权限。

HTTP 请求入站、WebSocket 每轮开始时冻结归属及价格；视频和批量图片把快照持久化到任务。管理员或站长改价只影响之后的请求。扣费事务内同时写入差价明细，费用和差价采用现有八位小数量化规则与请求幂等约束。余额预占不计收益，成功捕获/订阅消费才计；失败释放无收益。按任务创建前已有的旧任务不回填新归属。

收益只展示，不转余额、转账或提现。充值返佣沿用原账本和全局总开关，可与消费差价同时发生。管理员单独填写该站长作为一、二、三代受益人时的百分比：留空继承全局，0 停止对应层级。比例变更作用于后续返佣记账，不重算历史。总览的累计充值返佣包括该用户现有全部邀请返佣，消费差价只来自站长客户。

## 接口与配置

用户登录接口位于 `/api/v1/reseller`：`/access`、根概览、`/customers`、`/customers/:id/notes`、`/prices`、`/earnings`。管理员接口为 `/api/v1/admin/users/:id/reseller`，GET/PUT。未开放用户仅能读取自己的 access=false，其余站长操作返回 403。

根参数 `reseller-defaults.json` 定义默认倍率、最低倍率、分页大小。修改后运行 `python3 tools/generate_reseller_defaults.py` 并重新构建；生成 Go 常量与前端 JSON 编入同一个包，无新增运行时密钥或环境变量。

## Migration 277

在 276 后追加：四张新表 `reseller_profiles`、`reseller_customers`、`reseller_prices`、`reseller_earnings`；视频及批量图片任务各加一个可空 JSONB 快照。新表初始为空、旧任务快照为空，不改旧客户价格、不回填历史收益。建表和索引、任务表加列需要 DDL 锁，磁盘增量为新表/索引/WAL；后续账本按成功计费增长。

旧程序不理解新价格与收益，也不能为任务保留新快照。启用后不能仅回滚二进制；保留数据前滚修复，或停止所有 writer 后按已确认方案恢复程序与匹配数据。不得用旧备份覆盖已有新业务数据。本地候选使用本地备份验证，生产迁移遵循现有网页更新流程。
